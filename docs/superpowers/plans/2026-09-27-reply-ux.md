# Reply lifecycle and UX corrections

**Goal:** Allow another reply after a confirmed send, keep sent replies out of Drafts, provide explicit Save draft, reduce composer loading delays, and distinguish handled status from replying.

**Design:** Keep autosave and add Save draft to save and close the editor. Replace a sent editor with a compact confirmation and Reply again action. Rotate the accepted draft identity atomically before editing another reply; uncertain sends remain locked until reconciled. Load local draft text independently of provider recipient metadata, allow editing/saving while recipients load, and refresh recipients again on actual send. Cache private draft data only in memory. Use labeled Mark handled / Reopen controls with distinct checklist icons.

- [x] Backend: regression tests for accepted filtering, new draft identity/revision, stale requests, unknown-send blocking, and independent local draft/context reads; implement scoped APIs and demo equivalents.
- [x] Composer: test visible editing/sent/uncertain/loading states, implement Save draft and Reply again, preserve autosave and draft navigation safety, distinguish save/send loading feedback.
- [x] Loading: test local-draft preload deduplication and cache privacy, fresh thread reuse, and bounded provider body loading; integrate without speculative thread requests.
- [x] Drafts and reader: close saved editors, refresh Drafts immediately, label handled actions, keep responsive touch targets.
- [x] Verify with computer use on desktop/mobile, repeated simulated sends, drafts, delayed recipient loading and failures; run full tests/lint/typecheck/build and review.
- [ ] Commit focused files and push current main to its upstream.

**Root causes observed:** accepted records were returned in Drafts and rendered by a permanently locked editor; local draft GET awaited provider metadata (up to the provider timeout), reply-all could request it twice, and opening a cached conversation always refetched it. The handled undo icon closely resembled Reply.

## Verification evidence

- Full suite: 57 files passed, 575 tests passed, one skipped. Lint, TypeScript, and production build passed.
- Computer use in isolated demo and controlled-response fixtures: first send → Reply again → blank focused editor → Save draft → reopen from Drafts → second send removes the row and closes the editor. No real email was sent.
- Mobile widths 390 and 320: no horizontal overflow; distinct labeled handled controls, 44px toolbar targets, and explicit Send / Save actions. Saving restores focus to Reply; Drafts restores its row or heading.
- Holding recipient responses leaves the textarea editable and Save draft usable while Send waits for recipients. Fresh conversation opens reuse the cache.
- Lost send responses with both changed identity and changed text under the same identity keep old local text read-only; explicit Open current draft recovers the new text without overwriting it.
- A lost new-reply response recovers through Open current draft. A delayed send from unmounted editor A does not close or overwrite editor B. Save conflicts preserve local text and offer explicit recovery.
- Delayed provider fixture: six attachment bodies at 100ms each improved from 600ms serial to 200ms in bounded batches; this is fixture timing, not a live-provider latency claim.

Independent final review: 73 focused tests passed across six files; no remaining substantive blockers.
