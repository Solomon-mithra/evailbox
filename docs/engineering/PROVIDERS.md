# Email providers and Jev

## Contract and secrets

Server-only entry points are `src/lib/providers/index.ts` and `src/lib/jev.ts`. Token expiry is Unix epoch **milliseconds**. Refresh responses can omit `refreshToken`; retain the existing encrypted refresh token in that case. A rotated refresh token replaces the old one.

Gmail requires `NEXT_PUBLIC_GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`. Outlook requires `NEXT_PUBLIC_MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET`, and optionally `MICROSOFT_TENANT_ID` (default `common`, supporting personal and organizational Microsoft accounts when the registration allows both). Configure the exact callback URI from the application in each provider's app registration. Google Gmail access may require restricted-scope verification and a security assessment before broad production availability; development consent/test users are distinct from a verified production application.

OAuth uses authorization code + S256 PKCE. The caller owns a cryptographically random, single-use state, verifier storage and expiry, authenticated-user binding, callback origin validation, token encryption, and prevention of connecting one account to another user's mailbox. Provider scopes are `gmail.modify` and `offline_access Mail.ReadWrite Mail.Send User.Read` (current scopes), the least that support drafts, explicit replies and read/archive actions. Sync remains read-only; remote writes happen only in `providers/actions.ts` in response to an explicit user action. Connections made with earlier read-only scopes must reconnect to grant the new scopes; a 401/403 from an action surfaces `RECONNECT_REQUIRED`. Identity is fetched from the authorized provider, never accepted from callback query fields.

## Synchronization

Persist `cursor` as an opaque string and only advance it in the same database transaction as all message upserts/deletions from its `SyncPage`. Namespace provider message IDs by mailbox. Keep requesting pages while `hasMore` is true, subject to the service's time/page budget; resume the saved cursor on the next run. A thrown error means do not advance the cursor. A sync page may contain zero messages and still have more work.

- **Gmail:** new connections import up to the latest 100 Inbox messages in pages of 20 IDs, with the remaining allowance saved in the cursor. Capture history before listing and catch up from it when the cap is reached, ignoring further historical page tokens. Incremental additions may create rows; label/read changes update only already imported messages. Preserve the original history ID across history pages. Message-level 404, Inbox removal, spam and trash become tombstones. Expired bounded history reconciles from the oldest retained timestamp and admits only new arrivals or existing rows, preserving the 100-email initial scope. Legacy unbounded cursors remain readable.
- **Outlook:** new connections request Inbox delta references (`id,receivedDateTime`) ordered newest first, with immutable IDs. Hydrate and save at most 100 existing messages; continue consuming lightweight older references until Graph supplies a real delta token. This avoids Graph's 5,000-message filtered-delta limit. Newly arriving mail remains eligible during bootstrap even after the historical allowance is exhausted. Later deltas hydrate new mail and updates within the retained time window; older unknown updates cannot create rows. Follow exact validated next/delta URLs, process tombstones, and reconcile expired checkpoints without expanding the historical cache. Legacy v1 cursors retain their previous behavior.

On `reset: true`, start/persist `EmailAccount.rescanStartedAt`. Upsert observed messages in place and refresh `Email.lastSeenAt`; retain their local IDs, handled state and completed classifications. Continue across durable cursor pages, then only on the terminal page delete mailbox rows whose lastSeenAt predates the rescan start. Explicit provider tombstones still apply as observed. Never clear the whole cache at rescan start: that discards useful state and causes needless evaluation. Interrupted rescans preserve cached rows until completion. See [architecture](ENGINEERING.md) for durable scheduling and restart semantics.

Graph cursors require HTTPS, exact `graph.microsoft.com` hostname, no alternate port/credentials/hash, and a v1.0 `me/mailFolders/.../messages/delta` path. Validation occurs both before fetching and before persisting a returned link. Provider requests disallow redirects to prevent bearer-token forwarding. Network calls have at most 12-second timeouts, shortened to the shared worker deadline, and at most two retries for 429/5xx; `Retry-After` is honored up to five seconds, otherwise the request fails for the job scheduler to retry later. Authentication errors are not retried here. Provider failure messages contain status only, never response bodies or tokens.

Imported email bodies are never stored. Sync hashes the bounded normalized classification input for freshness and persists only summary fields. Normal imports reuse the fetched body inside the same durable step, keyed by account/message and matching content hash. Retries and later reclassification fetch plain text on demand with `fetchMessageText`: Gmail recursively decodes base64url `text/plain` MIME with charset support and skips attachments/HTML; Graph requests plain text and treats an HTML response as no body. Bodies are capped at 64,000 characters (24,000 sent to Jev) and discarded after evaluation; snippets are capped at 2,000. The reading view fetches full content live and falls back to the snippet. Provider HTML is sanitized and rendered in a sandboxed reader. A one-second hover/focus can warm the full message and HTTPS images in short-lived browser memory; the reader opens with images enabled and offers Hide images. Full documents remain excluded from persistent storage and HTTP caching; plain text is rendered as text. Explicit user-written reply drafts are persisted separately. Gmail web links use the provider message ID; Outlook links use an HTTPS allowlist of Outlook hosts.

## Native Jev evaluation

Pinned dependencies checked against installed types/source: `ai@7.0.108`, `@ai-sdk/gateway@4.0.88`.

`JEV_API_KEY` is required. `JEV_GATEWAY_URL` is the AI SDK Gateway **base URL**, default `https://ai-gateway.vercel.sh/v4/ai`; it is not a chat-completions URL or a direct TypeSafe API endpoint. The SDK appends `/evaluation-model`. A custom gateway must implement that evaluation protocol. HTTPS is mandatory. Do not put the key in any `NEXT_PUBLIC_*` environment variable.

The adapter calls `experimental_evaluate` using `createGateway(...).evaluation('typesafe-ai/jev')`. `classifyEmailAgainstTags` sends one shared email and up to 30 independent native boolean tag questions per call; each returns `P(tag match)`. Only missing tag/version pairs are requested by ordinary workers, including reuse of completed no-match and uncertain results. Generated q0/q1 question IDs map safely to unique caller tag IDs; incomplete/invalid answer sets throw. Zero tags make no call. The single-tag wrapper remains available. There is no chat request, generated JSON, or generated reasoning. The prompt identifies email content as untrusted evidence. Keywords/senders are supporting hints unless the user's tag prompt makes them mandatory. Evaluate at most 24,000 body characters plus the bounded subject/sender/snippet. This truncation can omit relevant evidence from unusually long messages.

`confidence` means `P(match) × 100`, not confidence in whichever decision won. At the default threshold 80, classify match at ≥80, no-match at ≤20, and uncertain in between. Threshold must be >50 and ≤100. `matched` is true only for a match. The returned `reasoning` is a deterministic probability/threshold trace, explicitly labeled as such. Do not market that trace as a model explanation or infer accuracy calibration from a probability. Invalid probabilities and upstream failures throw; they never become fabricated matches or no-matches. Timeout is the smaller of 20 seconds and the caller's remaining budget, with no in-request SDK retries; failed decisions remain pending for a later pass. Gateway request options require Zero Data Retention and disallow prompt training; unsupported provider routing should fail rather than silently weaken those requested controls.

A Gateway/provider HTTP 429 stops the classification batch, including calls for the other workspace. Completed decisions remain stored; failed and unattempted decisions remain pending. The user receives a rate-limit warning with a retry delay, and `workNotBefore` persists a cooldown of at least 60 seconds, extended by a valid `Retry-After` (seconds or HTTP date) or `retry-after-ms`. Manual work, tag edits and daily sync requests preserve this cooldown; the shared user lease enforces it. Scheduled work honors the larger of this delay and its normal failure backoff, while fresh mailbox ingestion may continue before inference resumes. The Jev cooldown is shared through `processing_state` and honored across users, with per-user retry state retained too. This is backoff, not a preallocated global provider-quota reservation.

`classification_failed` logs contain only status, a validated Gateway generation ID when present, and a retry delay for 429s. Never log the raw SDK error: its cause may include the full email request and provider response. A `gen_...` ID can be matched to Gateway logs without disclosing message contents. Batch API `classified` counts completed email/tag decisions. Inbox progress instead counts emails whose decisions are current for every tag, including no-match and uncertain outcomes; neither is the number of matching emails.

## Validation and remaining external checks

`tests/providers.test.ts` uses HTTP protocol fixtures for OAuth, identity, MIME decoding, history/delta pagination, expired cursors, deletion, hostile URLs, and error/retry handling. `tests/jev.test.ts` covers threshold decisions, malformed answers, inference failures, and a fixture request through the **real installed SDK** to assert the `/evaluation-model` URL, model headers, native question body and absence of chat messages. The Jev fixture also verifies three tag decisions use one actual SDK HTTP request with correctly mapped results. These tests make no live inbox or paid-model requests.

Before describing the service as externally validated, exercise consent and refresh-token rotation with authorized Gmail/Outlook test accounts, multi-page initial and incremental sync, read/unread changes, moved/deleted mail, expired cursor recovery, and the deployed callback URLs. Validate real Jev availability, account permissions, controls, latency and classification quality with an explicitly authorized synthetic evaluation. Run service-level concurrent-sync, transaction, tenant isolation, and expired-token tests as well; those responsibilities sit outside the provider adapters.
